# Central refresh and push delivery

Native 0.126.000 / Companion 0.50.0. Maintained source is currently `C:\Users\justc\.codex\worktrees\pixelvault-test-source\Codex`; the old checkout at `C:\Codex` is not the release source.

The existing automatic Windows service remains the owner of supported save readers and scheduled provider refreshes. It continues running when the desktop window is closed. No second agent process, account credentials, inbound port or data migration is introduced.

`RefreshUpdates` samples committed canonical data once per second (plus read time), independent of connected clients. It computes content versions for library summaries, tracker progress/definitions, source settings/status and achievement progress, including partial Centurian progress. Monitor heartbeats and unchanged provider observation timestamps do not invalidate visible content. Database stamps gate recomputation; this is a single coordinator rather than a catalogue scan per screen.

The coordinator publishes complete, bounded version snapshots with a process epoch, sequence, workspace identity and per-tracker/per-game versions. Slow subscribers retain only the latest snapshot. Reconnect always receives the current snapshot, so no unbounded event history is required. Clients compare versions and read authoritative data through their existing account-scoped stores. Events cannot award achievements or bypass review.

- Web: authenticated, same-origin server-sent events at `/api/v1/refresh/events?workspace=…`; workspace mismatch is rejected. Connections renew at most every five minutes to recheck authentication. The browser stops polling while connected, retains the newest notice during edits/dialogs, retries unsuccessful reads, and catches up when visible again. Existing periodic polling is the compatibility/outage fallback.
- Desktop: the service atomically replaces `refresh-updates.json` in the existing protected application-data directory. `LocalRefreshListener` receives filesystem notifications, debounces them and reconciles the small file every 30 seconds to cover missed notifications. A 15-second heartbeat lets it recognize a stale coordinator. The file contains versions and connection status, not credentials or tracker values. Desktop consumers retain their own account checks.
- Native views: tracker windows/dashboard, Achievement Hub, achievement details, game-profile achievements and notification history consume saved changes. Hub refreshes triggered by push never call provider APIs. Tracker editor draft guards remain in place; open tracker fallback checks slow from two to 30 seconds while the coordinator is healthy. Existing standalone refresh behavior remains available when the service is absent.

Acquisition and delivery remain separate. Save readers keep existing stabilization, source leases, automatic modes, pause, manual-progress protection, backoff and review checks. Provider intervals remain user-configured (currently 15 minutes, with the existing five-minute minimum and failure backoff). The scheduler now revisits due work every 15 seconds instead of waiting another five minutes. This release improves delivery of saved results; it does not promise provider-side real-time achievement data or move unsupported Native-only adapters into the service.

Validation covers authenticated streaming, workspace isolation, timestamp-only changes, coalescing/reconnect, real browser SSE without idle polling, deferred edits, failed-read retries, persistent unlock acknowledgement, local file replacement/restarts, window subscription cleanup and saved-only Hub reads. Existing achievement/source authority tests remain applicable. Evidence and release verification: `C:\Codex\artifacts\central-refresh`.

Implementation references: [EventSource](https://developer.mozilla.org/en-US/docs/Web/API/EventSource), [FileSystemWatcher](https://learn.microsoft.com/en-us/dotnet/api/system.io.filesystemwatcher?view=net-8.0). Filesystem notifications are hints; the canonical stores and periodic reconciliation remain authoritative.
