## Implemented behavior

- The Windows server supports an explicit `--installation-config` and the .NET Windows service lifetime. Configuration must name direct-local roots and listen addresses; invalid/empty service configuration fails before owner-store initialization. It cannot select a default historical workspace.
- A durable local refresh queue replaces NAS request/lease transport in direct mode. Authenticated browser requests enqueue work; headless readers execute outside HTTP requests. Reviews, request IDs, snapshots and interrupted jobs persist in Companion state. Completed job retention is bounded; pending reviews are retained.
- Reads use the existing Native JSON/Death Stranding adapters and validated save-copy/isolated-decoder path. `PixelVault.exe --companion-readers` runs before WPF and Velopack initialization. It never starts Native UI, assumes no signed-in profile, and receives explicit application/cache roots. Other Native-only adapters continue to be owned by Native.
- Shared repository commands preserve source permissions, account scope, manual conflicts, older/undone-save reviews, notes, history, first-unlock evidence and source protections. Permission/definition revisions are checked again after reading. Reconfiguration or pause cancels automatic application. A stale manual review must be reloaded; an older save requires the existing explicit approval.
- Native and Companion use cross-process source locks. A live canonical background-owner lock delegates supported automatic work to the service. Native's other adapters and deliberate manual refreshes remain available. Shared handled signatures survive restarts. Native/browser On Open events use durable signals, so the service can honor that mode while Native is open.
- Global pause remains in Companion state; per-tracker Manual/On Open/Save Changes/Periodic settings remain canonical. The captured PC has seven unpaused Save Changes configurations; the other linked trackers retain manual behavior. No real automatic worker was enabled during rehearsal.
- Provider jobs reuse Native fetching, score rules and cache merging for the approved Steam/RetroAchievements accounts. Cross-process account-file leases and captured request times prevent lost updates and older responses overwriting newer data. Native's automatic notification monitor consumes saved results while the background owner is active; foreground fetches remain available. The service respects the existing notification enable/interval settings (default 15 minutes, zero disables) and a 30-minute failure delay. Provider jobs remain disabled as an explicit rehearsal policy. Both provider credentials have now passed actual packaged-reader fetches under the service identity without enabling recurring work.
- Save readers, provider jobs and photo conversion have separate bounded work paths. Windows job objects terminate reader/decoder children when their owning host exits; timeout/cancellation also terminates owned processes. [Microsoft documents job membership and kill-on-close behavior](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects). Runtime diagnostics are bounded, and private reader errors are kept out of browser responses.
- Direct-mode browser controls now expose local refresh, pause/resume and pending reviews without connector pairing. The connector replication endpoints remain disabled in direct mode.
